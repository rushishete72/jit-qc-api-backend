# 🛠️ Utility Services (src/utils)

यह फ़ोल्डर Express API के लिए सभी कोर, पुन: प्रयोज्य (reusable) हेल्पर फ़ंक्शन्स और क्लासेस को रखता है। ये यूटिलिटीज डेटा अखंडता (data integrity), एसिंक्रोनस ऑपरेशन, त्रुटि प्रबंधन और बाहरी सेवाओं (जैसे ईमेल) के साथ इंटरैक्शन को संभालती हैं।

## 1. `errorHandler.js`

**उद्देश्य:** API में एक मानक, केंद्रीकृत त्रुटि प्रबंधन प्रणाली (centralized error handling system) प्रदान करना। यह सुनिश्चित करता है कि क्लाइंट को हमेशा पठनीय (readable) और मानकीकृत (standardized) JSON त्रुटि प्रतिक्रियाएँ मिलें, भले ही आंतरिक रूप से कोई भी त्रुटि उत्पन्न हुई हो।

| फ़ंक्शन/क्लास | प्रभाव क्षेत्र | कार्यक्षमता का सारांश |
| :--- | :--- | :--- |
| **`APIError`** (Class) | सभी राउट्स और नियंत्रक (Controllers) | एक कस्टम JavaScript `Error` क्लास। डेवलपर्स इसका उपयोग विशिष्ट HTTP स्टेटस कोड (जैसे 400, 404, 401) के साथ त्रुटियाँ बनाने के लिए करते हैं। |
| **`errorHandlerMiddleware`** (Middleware) | `src/app.js` (सबसे अंत में) | Express पाइपलाइन द्वारा पकड़ी गई सभी त्रुटियों को कैप्चर करता है। यह `APIError` ऑब्जेक्ट को पढ़ता है और क्लाइंट को एक साफ `{"success": false, "message": "..."}` JSON प्रतिक्रिया भेजता है। |

## 2. `asyncHandler.js`

**उद्देश्य:** एसिंक्रोनस (Async/Await) फ़ंक्शन्स के लिए Express में त्रुटि प्रबंधन को सरल बनाना।

| फ़ंक्शन/क्लास | प्रभाव क्षेत्र | कार्यक्षमता का सारांश |
| :--- | :--- | :--- |
| **`asyncHandler(fn)`** (Function) | सभी एसिंक्रोनस राउट हैंडलर्स | यह किसी भी `async` एक्सप्रेस राउट हैंडलर को रैप करता है। यदि async फ़ंक्शन विफल हो जाता है, तो यह स्वचालित रूप से त्रुटि को पकड़ता है और उसे `next()` में पास कर देता है, जहाँ से वह `errorHandlerMiddleware` में चली जाती है। **इससे आपको प्रत्येक राउट हैंडलर में `try...catch` ब्लॉक लिखने की आवश्यकता समाप्त हो जाती है।** |

## 3. `validation.js`

**उद्देश्य:** सभी डेटा इनपुट (आमतौर पर `req.body` से) के लिए कठोर सत्यापन (strict validation) तर्क को समाहित (encapsulate) करना।

| फ़ंक्शन/क्लास | प्रभाव क्षेत्र | कार्यक्षमता का सारांश |
| :--- | :--- | :--- |
| **`tr(s)`** (Helper) | आंतरिक सत्यापन फ़ंक्शन्स | स्ट्रिंग्स को ट्रिम करता है और सुनिश्चित करता है कि वे अमान्य (`null`/`undefined`) न हों। |
| **`isNumeric(value)`** (Helper) | आंतरिक सत्यापन फ़ंक्शन्स | यह जाँच करता है कि कोई मान संख्या (Number) है या नहीं, वैकल्पिक (optional) खाली मानों को अनुमति देता है। |
| **`generateOtp()`** (Helper) | Authentication (User) राउट्स | 6 अंकों का रैंडम OTP जनरेट करता है। |
| **`handleEmailValidation(email)`** (Helper) | Supplier, Client, और User राउट्स | ईमेल फ़ॉर्मेट, उपस्थिति (presence), और लंबाई (length) की जाँच के लिए मास्टर फ़ंक्शन। |
| **`validatePartCreation()`** (Master Validation) | Part Master Controller | यह सुनिश्चित करता है कि नए पार्ट बनाने के लिए सभी आवश्यक फ़ील्ड (Part No, Rev No, UOM ID, आदि) मान्य हों। |
| **`validateSupplierCreation()`** (Master Validation) | Supplier Master Controller | यह सुनिश्चित करता है कि नए सप्लायर बनाने के लिए आवश्यक फ़ील्ड (Name, Code, Created By) मान्य हों और ईमेल/फ़ोन सही फ़ॉर्मेट में हों। |
| **अन्य `validate*` फ़ंक्शन्स** | संबंधित Controllers | यह डेटा अखंडता सुनिश्चित करने के लिए सभी प्रमुख Master Entities (UOM, Stock Status, Client, QC Lot, आदि) के निर्माण और अद्यतन (update) के लिए इनपुट को सत्यापित करता है। |

## 4. `emailSender.js`

**उद्देश्य:** Nodemailer का उपयोग करके बाहरी ईमेल भेजने की सेवा को संभालना।

| फ़ंक्शन/क्लास | प्रभाव क्षेत्र | कार्यक्षमता का सारांश |
| :--- | :--- | :--- |
| **`transporter`** (Nodemailer Object) | केवल आंतरिक उपयोग | `.env` में दिए गए SMTP क्रेडेंशियल्स के आधार पर सशर्त रूप से (conditionally) इनिशियलाइज़ होता है। यदि क्रेडेंशियल्स अनुपस्थित हैं, तो यह ईमेल सेवा को अक्षम (disable) कर देता है। |
| **`sendEmail({...})`** (Function) | Authentication/User/Notification Services | एक सामान्यीकृत इंटरफ़ेस प्रदान करता है। यह `to`, `subject`, `text`, और `html` स्वीकार करता है, ईमेल भेजता है, और किसी भी SMTP त्रुटि को पकड़कर उसे `ErrorHandler` के रूप में थ्रो करता है। |
