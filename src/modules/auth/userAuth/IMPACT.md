# 📝 IMPACT.md: `src/modules/auth/userAuth` फ़ोल्डर विश्लेषण

यह दस्तावेज़ `src/modules/auth/userAuth` फ़ोल्डर के भीतर चार मुख्य घटकों के **डिजाइन, कार्यक्षमता और व्यावसायिक प्रभाव** का विस्तार करता है, जो API की प्रमाणीकरण (Authentication) और प्राधिकरण (Authorization) नींव को परिभाषित करते हैं।

---

## 1. `userAuth.model.js` (डेटाबेस प्रबंधन)

### 🔑 प्रमुख कार्यक्षमताएँ (Key Functionality)

| फ़ंक्शन (Function) | विवरण (Description) | तकनीकी प्रभाव (Technical Impact) |
| :--- | :--- | :--- |
| `ensureDefaultRoleExists` | DB में 'Client' जैसी डिफ़ॉल्ट भूमिका (role) की उपस्थिति सुनिश्चित करता है। | **CRITICAL FIX**: DB सेटअप विफलता को रोकता है। `roles` तालिका में एंट्री की गारंटी देता है। |
| `getUserByEmail` | सक्रिय (active) उपयोगकर्ता को भूमिका के साथ पुनर्प्राप्त करता है। | उपयोगकर्ता की त्वरित पहचान के लिए आधार। |
| `registerUser` | एक नया उपयोगकर्ता बनाता है और उसे डिफ़ॉल्ट भूमिका से लिंक करता है। | **डेटा अखंडता**: डुप्लिकेट ईमेल पर 409 त्रुटि (Unique Constraint) देता है। |
| `createOtp` | OTP को जेनरेट करता है, उसे bcrypt के साथ **Hash** करता है, और 5 मिनट की समाप्ति (expiry) के साथ DB में संग्रहीत करता है। | **सुरक्षा**: OTP को सादे पाठ (plain text) में स्टोर करने से रोकता है। |
| `validateOtp` | OTP की समाप्ति, प्रयासों की संख्या और हैश मिलान (hash match) की जाँच करता है। सफल होने पर `is_verified` को TRUE पर सेट करता है। | **एंटी-ब्रूट फ़ोर्स**: विफल प्रयासों के लिए काउंटर लागू करता है और एक्सपायरी जाँच करता है। |
| `getUserProfileData` | उपयोगकर्ता प्रोफ़ाइल, भूमिका, और **सभी संबंधित अनुमतियों (Permissions)** को एक एकल SQL क्वेरी में पुनर्प्राप्त करता है। | **PBAC सक्षम करना**: JWT टोकन पेलोड के लिए आवश्यक सभी डेटा कुशलतापूर्वक प्रदान करता है। |

### 📈 व्यावसायिक प्रभाव (Business Impact)

यह फ़ाइल **डेटा अखंडता**, एन्क्रिप्शन और अनुमतियों (Permissions) को कुशलतापूर्वक लोड करके API के लिए **उच्च-सुरक्षा नींव** सुनिश्चित करती है।

## 2. `userAuth.controller.js` (एप्लिकेशन लॉजिक)

### 🔑 प्रमुख कार्यक्षमताएँ (Key Functionality)

| फ़ंक्शन (Function) | विवरण (Description) | तकनीकी प्रभाव (Technical Impact) |
| :--- | :--- | :--- |
| `createAuthToken` | PBAC अनुमतियों को शामिल करते हुए उपयोगकर्ता प्रोफ़ाइल के आधार पर JWT टोकन बनाता है। | **AUTHORIZATION**: `role` और `permissions` को सीधे JWT में एम्बेड करता है, जिससे `auth.js` मिडलवेयर में DB कॉल की आवश्यकता समाप्त हो जाती है। |
| `registerUser` | अनुरोध (request) को मान्य करता है, उपयोगकर्ता को मॉडल के माध्यम से रजिस्टर करता है, और OTP ईमेल भेजने के लिए सेवा को कॉल करता है। | **यूजर फ़्लो**: पंजीकरण (Registration) और OTP अनुरोध के बीच समन्वय (Coordination)। |
| `loginUser` | ईमेल द्वारा उपयोगकर्ता को ढूंढता है और OTP ईमेल भेजता है। | **Passwordless Login** फ़्लो को लागू करता है। |
| `verifyOtp` | OTP को मान्य करता है, प्रोफ़ाइल (Permissions के साथ) पुनर्प्राप्त करता है, और JWT जारी करता है। | **CRITICAL ENTRY POINT**: सफल प्रमाणीकरण (Authentication) के बाद एक्सेस टोकन प्रदान करता है। |
| `resetPassword` | OTP सत्यापन के बाद उपयोगकर्ता का पासवर्ड अपडेट करता है। | **सुरक्षा पुनर्प्राप्ति (Security Recovery)**: सुनिश्चित करता है कि पासवर्ड अपडेट से पहले उपयोगकर्ता को OTP के माध्यम से मान्य किया जाता है। |

### 📈 व्यावसायिक प्रभाव (Business Impact)

कंट्रोलर **पासवर्ड रहित प्रमाणीकरण** को लागू करके उपयोगकर्ता घर्षण (friction) को कम करता है और `APIError` का उपयोग करके मानकीकृत, स्पष्ट HTTP त्रुटि प्रतिक्रियाएँ सुनिश्चित करता है।

## 3. `userAuth.service.js` (व्यावसायिक तर्क/Business Logic)

### 🔑 प्रमुख कार्यक्षमताएँ (Key Functionality)

| फ़ंक्शन (Function) | विवरण (Description) | तकनीकी प्रभाव (Technical Impact) |
| :--- | :--- | :--- |
| `sendOtpVerificationEmail` | OTP जनरेट करता है (`utils/validation`), उसे मॉडल में स्टोर करता है (`userAuth.model`), और ईमेल भेजता है (`utils/emailSender`)। | **विश्वसनीयता**: ईमेल विफल होने पर DB से OTP रिकॉर्ड को हटाकर **ट्रांज़ेक्शनल सफाई (Transactional Cleanup)** सुनिश्चित करता है। |
| `handleAuthFlow` | जाँच करता है कि उपयोगकर्ता मौजूद है या नहीं। यदि नहीं, तो रजिस्ट्रेशन की आवश्यकता है या 404 त्रुटि भेजता है। यदि निष्क्रिय है, तो 403 त्रुटि भेजता है। | **फ़्लो एन्कैप्सुलेशन**: यह तय करता है कि उपयोगकर्ता किस फ़्लो (पंजीकरण/लॉगिन) से होकर गुज़रेगा। |
| **त्रुटि प्रबंधन फिक्स** | `ErrorHandler` के बजाय `APIError` का उपयोग करता है। | **कोहेरेंस**: संपूर्ण एप्लिकेशन में त्रुटि ऑब्जेक्ट के उपयोग को मानकीकृत करता है। |

### 📈 व्यावसायिक प्रभाव (Business Impact)

यह सेवा परत OTP फ़्लो की **विश्वसनीयता** सुनिश्चित करती है और OTP/ईमेल कॉन्फ़िगरेशन विवरण से कंट्रोलर को अलग करती है, जिससे कोड का रखरखाव आसान हो जाता है।

## 4. `userAuth.route.js` (एंडपॉइंट परिभाषा)

### 🔑 प्रमुख कार्यक्षमताएँ (Key Functionality)

| एंडपॉइंट (Endpoint) | विधि (Method) | कंट्रोलर फ़ंक्शन | तकनीकी प्रभाव (Technical Impact) |
| :--- | :--- | :--- | :--- |
| `/register` | `POST` | `registerUser` | नए उपयोगकर्ताओं के लिए API प्रवेश बिंदु। |
| `/login` | `POST` | `loginUser` | OTP अनुरोध (request) के लिए API प्रवेश बिंदु। |
| `/verify-otp` | `POST` | `verifyOtp` | JWT जारी करने का प्राथमिक एंडपॉइंट। |
| `/reset-password` | `POST` | `resetPassword` | पासवर्ड पुनर्प्राप्ति फ़्लो। |
| `/logout` | `GET` | `logoutUser` | क्लाइंट को JWT हटाने के लिए संकेत (signal) देता है। |

### 📈 व्यावसायिक प्रभाव (Business Impact)

राउटिंग फ़ाइल `/api/auth` उपसर्ग (prefix) के तहत **स्वच्छ और सहज (intuitive) API संरचना** प्रदान करती है, जिससे API का उपयोग करने वाले फ्रंटएंड डेवलपर्स के लिए एंडपॉइंट्स को समझना आसान हो जाता है।
